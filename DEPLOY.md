# Деплой Hidden Liders на Railway

Игра деплоится как **два отдельных сервиса из одного репозитория**: бэкенд
(FastAPI) и фронтенд (Next.js). Всё, что можно было подготовить в коде, уже
готово — конфиги сборки лежат в `src/back/railway.json` и `src/front/railway.json`,
версии рантаймов закреплены (`src/back/.python-version` → Python 3.13,
`src/front/.nvmrc` → Node 22). Railway подхватит их сам.

Руками в Railway нужно сделать только три вещи: указать Root Directory, задать
переменные окружения и выдать домены.

## Важно: порядок действий

Между сервисами есть циклическая зависимость, поэтому порядок именно такой:

- фронту нужен адрес бэкенда **на момент сборки** (`NEXT_PUBLIC_API_URL`
  вшивается в JS при `next build`, а не читается в рантайме);
- бэкенду нужен адрес фронта для CORS.

Разрывается это так: сначала бэкенд с временным `CORS_ORIGINS=*`, потом фронт с
реальным адресом бэкенда, потом возврат к бэкенду за настоящим CORS.

---

## Шаг 1. Проект и сервис бэкенда

1. [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub
   repo** → `Faskat/Hidden_liders`. Если Railway не видит репозиторий — в
   настройках GitHub-приложения Railway дай ему доступ к нему.
2. Первый сервис создастся автоматически. Открой его → **Settings**:
   - **Root Directory**: `src/back`
   - **Branch**: `main` (по умолчанию так и есть)
3. Первый деплой может упасть или собрать не то — это нормально, Root Directory
   применяется со следующей сборки.

## Шаг 2. Переменные бэкенда

Вкладка **Variables** сервиса бэкенда:

| Переменная     | Значение | Обязательна |
|----------------|----------|-------------|
| `CORS_ORIGINS` | `*` (временно, поменяем на шаге 5) | да |
| `LOG_LEVEL`    | `INFO`   | нет |

Что задавать **не нужно**:

- `PORT` — Railway выставляет сам, `run.py` его читает;
- `DATABASE_URL` — по умолчанию SQLite в `./data/events.db`.

При `CORS_ORIGINS=*` бэкенд автоматически отключает `allow_credentials` —
иначе браузер отбрасывает ответ. С явным доменом credentials включаются обратно.

## Шаг 3. Домен бэкенда

**Settings → Networking → Generate Domain**. Получится что-то вроде
`hidden-liders-back-production.up.railway.app`.

Проверь, что живой (домен вставь свой):

```bash
curl https://hidden-liders-back-production.up.railway.app/health
```

Ожидаемый ответ: `{"status":"ok"}`.

И что каталог карт загрузился:

```bash
curl https://hidden-liders-back-production.up.railway.app/ready
```

Ожидаемый ответ: `{"status":"ready"}`. Если прилетает 503 с
`CARDS_NOT_LOADED` — значит не видно `src/back/data/cards.json` (обычно из-за
неправильного Root Directory или volume, см. «Хранение партий»).

**Скопируй URL бэкенда — он нужен на следующем шаге.**

## Шаг 4. Сервис фронтенда

1. В том же проекте: **New** → **GitHub Repo** → тот же `Faskat/Hidden_liders`.
2. Сервис → **Settings** → **Root Directory**: `src/front`.
3. Сервис → **Variables**, **до первой сборки**:

   | Переменная            | Значение |
   |-----------------------|----------|
   | `NEXT_PUBLIC_API_URL` | `https://<домен-бэкенда>` — без слэша в конце |

4. **Settings → Networking → Generate Domain** — это и есть публичный адрес игры.

Если переменную задал уже после сборки или поменял позже — нужен **Redeploy**
фронта. Пересборка обязательна: адрес вшивается в бандл.

## Шаг 5. Замкнуть CORS

Вернись в сервис бэкенда → Variables → замени:

```
CORS_ORIGINS=https://<домен-фронта>
```

Без слэша в конце. Бэкенд передеплоится сам. Если фронтов несколько (например,
свой домен + railway-поддомен) — перечисли через запятую, без пробелов.

## Шаг 6. Проверка

- [ ] `/health` бэкенда отвечает `{"status":"ok"}`
- [ ] `/ready` отвечает `{"status":"ready"}`
- [ ] Открывается главная фронта, создаётся комната, виден код
- [ ] Второй игрок заходит по коду с другого устройства и попадает в лобби
- [ ] Игра стартует, ходы проходят
- [ ] В консоли браузера (F12) нет ошибок CORS
- [ ] В хабе `faskat-hq` вписать адрес фронта в `UPLINK_CONF.hidden_liders.pub`

## Хранение партий между деплоями (опционально)

По умолчанию SQLite лежит внутри контейнера и **обнуляется при каждом деплое**:
все комнаты пропадают. Для игры «на вечер» это нормально. Если нужно сохранять:

1. Сервис бэкенда → **Add Volume**, Mount path: `/data`.
   Именно `/data`, **не** `/app/data` — иначе volume перекроет собой
   `data/cards.json` и каталог карт перестанет читаться (`/ready` вернёт 503).
2. Variables → `DATABASE_URL=sqlite:////data/events.db`
   (четыре слэша — это абсолютный путь `/data/events.db`).

## Если что-то не работает

**Сборка фронта падает на «Linting and checking validity of types»** — ошибка
типов в коде. Воспроизводится локально: `cd src/front && npx tsc --noEmit`.

**Страница открывается, но игра не грузится; в консоли «Failed to fetch» или
ошибка CORS** — три причины по частоте:
1. `NEXT_PUBLIC_API_URL` задан после сборки → сделай Redeploy фронта;
2. в адресе лишний слэш в конце или `http://` вместо `https://`;
3. `CORS_ORIGINS` на бэкенде не совпадает с доменом фронта (шаг 5).

Проверить, какой адрес реально вшит в бандл, можно прямо в браузере: F12 →
Network → посмотреть, куда уходят запросы.

**502 / Application failed to respond** — сервис не слушает нужный порт. Проверь,
что не задал `PORT` руками и что Root Directory правильный.

**Комнаты пропали после деплоя** — ожидаемо без volume, см. раздел выше.

**Игра не стартует, «Каталог карт не завантажено»** — `/ready` вернёт причину;
почти всегда это volume, смонтированный в `/app/data`.

## Локальный запуск (как раньше)

- бэк: `start-backend.bat` (порт 8000)
- фронт: `start-frontend.bat` (порт 3000, `NEXT_PUBLIC_API_URL` из `.env.local`)
