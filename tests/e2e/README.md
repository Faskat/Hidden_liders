# E2E-перевірки анімацій столу

Перевіряють те, що бачить гравець: карта вилітає звідти, куди її поклали, і
прилітає туди, де вона врешті лежить. Не «щось поворухнулося».

```bash
pip install -r tests/e2e/requirements.txt
cd tests/e2e && python -m pytest -q
```

Нічого піднімати руками не треба: набір сам запускає бекенд і фронт на
власних портах (8010 і 3010) і сам їх гасить. Потрібен лише встановлений
Chrome — драйвер Selenium дістає сам.

## Чому свій стенд, а не той, що вже піднято

Бекенд тримає в пам'яті рівно десять кімнат і не витісняє жодної
(`src/back/session.py:47`). Набір, запущений поверх сервера, на якому вже
грали руками, впирався б у цей ліміт десь на середині — і падав би не там, де
насправді помилка. Свій стенд заразом означає власну тимчасову базу: тести не
пишуть у робочу `src/back/data/events.db`.

Готовий стенд можна підсунути змінними — тоді набір нічого не запускає:

```bash
E2E_API=http://localhost:8000/v1 E2E_WEB=http://localhost:3000 python -m pytest -q
```

Перший запуск довший на десятки секунд: `next dev` складає сторінки під час
першого запиту. Сторінки прогріваються один раз перед першим тестом.

## Як це влаштовано

Пікселі не порівнюються. Замість цього `probe.js` вставляється в сторінку ще
до застосунку і підміняє `Element.animate` — єдину точку, через яку проходить
кожен рух на столі. З кожної анімації знімається маршрут: перший і останній
кадр перетворюються на пару зон.

Назви зон беруться з реєстру самого застосунку (`window.__hlDebug`, шов у
`ZoneAnchors.tsx`), тому в очікуваннях стоять ті самі `hand:<id>`,
`party:<id>`, `tavern:0`, `harbor`, що й у коді режисера, — і жодного
селектора по верстці.

Партією керує HTTP, браузер лише дивиться. Клікати картами не вийшло б:
половина з них відкриває вікно вибору цілі, і тест перевіряв би верстку
модалок замість польотів.

## Що перевіряється

| файл | про що |
|---|---|
| `test_deal_scene.py` | роздача: маршрути, порядок таверни, тривалість, масштаб на 4 гравців |
| `test_turn_animations.py` | розіграш, добір із таверни й гавані, скид, поповнення, чужий хід |
| `test_card_visibility.py` | карта з'являється лише після прильоту; reduced-motion; пропуск сцени |
| `test_board_effects.py` | підсвітка панелі при передачі ходу, спалах треку й лідери на кінці гри |
| `test_ability_animations.py` | вбивство, переворот, обмін руками, перетасовка, `CardMoved` |

## Два тестові шви в застосунку

Обидва вирізаються з продакшн-збірки перевіркою `NODE_ENV`.

- `window.__hlDebug` (`ZoneAnchors.tsx`) — реєстр зон. Без нього тест
  вгадував би зону селектором і переписувався б після кожної правки верстки.
- `window.__hlFeed` / `window.__hlView` (`page.tsx`) — подати подію режисерові
  напряму й прочитати намальований стан. Половина анімацій висить на
  здібностях карт, а яка карта кому дістанеться, вирішує `random` на бекенді;
  чекати потрібної здібності живою грою означало б лишити тест плаваючим.
  Живі сценарії шов не підміняє — розіграш, добір, скид і роздача
  перевіряються справжньою грою.

## Межі

Набір не бачить пікселів: він доводить, що анімація створена з правильними
кадрами, а не що вона гарно виглядає. Плавність, дуга й тайминг лишаються на
живе око.
